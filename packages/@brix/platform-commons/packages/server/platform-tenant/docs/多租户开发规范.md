## 1. 概述

本文档定义了在 Brix Platform 上开发多租户功能的规范和最佳实践。所有开发人员必须遵循这些规范，以确保租户数据安全隔离。

### 1.1 多租户架构原则

```text
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                              多租户安全模型                                              │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                          │
│  原则 1：默认隔离（Isolation by Default）                                                │
│  ═══════════════════════════════════════════════════════════════════════════════════════│
│  所有业务数据默认按租户隔离，跨租户访问需显式声明                                        │
│                                                                                          │
│  原则 2：租户上下文传递（Context Propagation）                                           │
│  ═══════════════════════════════════════════════════════════════════════════════════════│
│  租户 ID 通过 TenantContext 在整个请求链路中传递                                        │
│                                                                                          │
│  原则 3：引用一致性（Reference Integrity）                                               │
│  ═══════════════════════════════════════════════════════════════════════════════════════│
│  实体间引用必须验证租户归属，禁止跨租户引用                                              │
│                                                                                          │
│  原则 4：SQL 自动过滤（Auto SQL Filtering）                                              │
│  ═══════════════════════════════════════════════════════════════════════════════════════│
│  所有对业务表的查询自动添加 tenant_id 条件                                               │
│                                                                                          │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. 红线规则（禁止事项）

### 2.1 绝对禁止

| 序号 | 红线规则 | 后果 |
|------|---------|------|
| R1 | **禁止业务表缺少 tenant_id 字段** | 数据泄露风险 |
| R2 | **禁止绕过 TenantInterceptor 执行原生 SQL** | 数据泄露风险 |
| R3 | **禁止在不同租户间共享业务实体引用** | 数据隔离破坏 |
| R4 | **禁止在异步任务中遗漏 TenantContext 传播** | 上下文丢失 |
| R5 | **禁止使用 @CrossTenantAccess 而不填写 reason** | 审计追踪缺失 |
| R6 | **禁止在唯一约束中遗漏 tenant_id** | 数据冲突风险 |

### 2.2 红线检测

```java
// ❌ 错误示例：缺少 tenant_id 的唯一约束
@Table(uniqueConstraints = @UniqueConstraint(columnNames = {"code"}))
public class Product { }

// ✅ 正确示例：包含 tenant_id 的唯一约束
@Table(uniqueConstraints = @UniqueConstraint(columnNames = {"tenant_id", "code"}))
public class Product { }
```

## 3. 开发规范

### 3.1 实体定义

#### 业务实体必须继承 TenantOwnedEntity

```java
/**
 * 正确的业务实体定义示例
 */
@Entity
@Table(
    name = "biz_order",
    uniqueConstraints = {
        @UniqueConstraint(
            name = "uk_order_number",
            columnNames = {"tenant_id", "order_number"}
        )
    }
)
public class Order extends TenantOwnedEntity {

    @Column(name = "order_number", nullable = false, length = 64)
    private String orderNumber;

    @Column(name = "customer_id", nullable = false)
    private Long customerId;

    // ... getter/setter
}
```

#### 表命名规范

| 表类型 | 前缀 | 示例 | 是否隔离 |
|--------|------|------|---------|
| 系统表 | `sys_` | sys_tenant, sys_identity | 否（白名单） |
| 业务表 | `biz_` | biz_order, biz_customer | 是 |
| 审计表 | `biz_audit_` | biz_audit_log | 是 |

### 3.2 Repository 定义

```java
/**
 * Repository 应继承基础接口，自动获得租户过滤能力
 */
@Repository
public interface OrderRepository extends JpaRepository<Order, Long> {

    // ✅ 正确：通过 TenantInterceptor 自动过滤
    List<Order> findByStatus(OrderStatus status);

    // ❌ 错误：原生 SQL 需要手动添加 tenant_id
    @Query(value = "SELECT * FROM biz_order WHERE status = ?1", nativeQuery = true)
    List<Order> findByStatusNative(String status);

    // ✅ 正确：原生 SQL 包含 tenant_id 条件
    @Query(value = "SELECT * FROM biz_order WHERE tenant_id = ?1 AND status = ?2", nativeQuery = true)
    List<Order> findByTenantAndStatusNative(String tenantId, String status);
}
```

### 3.3 Service 层规范

#### 引用验证

```java
@Service
public class OrderService {

    private final TenantReferenceValidator validator;
    private final CustomerRepository customerRepository;

    public Order createOrder(CreateOrderRequest request) {
        // 步骤 1：获取当前租户
        String currentTenantId = TenantContext.getCurrentTenantId();

        // 步骤 2：查询引用实体
        Customer customer = customerRepository.findById(request.getCustomerId())
            .orElseThrow(() -> new InvalidReferenceException(
                "Order", null, "customerId", request.getCustomerId(), "Customer"
            ));

        // 步骤 3：验证租户一致性
        validator.validateReferenceFromContext(
            customer.getTenantId(),
            "Order", null,
            "Customer", customer.getId(),
            "customerId"
        );

        // 步骤 4：创建订单（安全）
        Order order = new Order();
        order.setCustomerId(customer.getId());
        order.setTenantId(currentTenantId); // 由 TenantOwnedEntity 自动设置
        
        return orderRepository.save(order);
    }
}
```

### 3.4 异步任务处理

```java
@Service
public class AsyncOrderProcessor {

    private final ExecutorService executor;

    public void processOrderAsync(Order order) {
        // ✅ 正确：使用 TenantContext.wrap() 传播上下文
        Runnable task = TenantContext.wrap(() -> {
            // 在异步线程中，TenantContext 已正确设置
            String tenantId = TenantContext.getCurrentTenantId();
            processOrder(order, tenantId);
        });

        executor.submit(task);
    }

    // ❌ 错误：直接提交任务，租户上下文丢失
    public void processOrderAsyncWrong(Order order) {
        executor.submit(() -> {
            // ⚠️ TenantContext.getCurrentTenantId() 会抛出异常！
            processOrder(order, TenantContext.getCurrentTenantId());
        });
    }
}
```

### 3.5 跨租户访问

```java
/**
 * 跨租户访问必须使用 @CrossTenantAccess 注解
 * 并提供明确的业务原因
 */
@Service
public class PlatformAnalyticsService {

    /**
     * 统计所有租户的订单总量
     * 
     * 此方法需要跨租户访问，因为平台管理员需要查看整体业务指标
     */
    @CrossTenantAccess(reason = "Platform-level order analytics for admin dashboard")
    public OrderAnalytics calculatePlatformOrderStats() {
        // 进入跨租户作用域
        TenantSqlGuardInterceptor.enterCrossTenantScope(
            "Platform-level order analytics for admin dashboard"
        );
        
        try {
            return analyticsRepository.calculatePlatformStats();
        } finally {
            TenantSqlGuardInterceptor.exitCrossTenantScope();
        }
    }
}
```

## 4. 常见问题（FAQ）

### Q1: 为什么我的查询返回空结果？

**可能原因**：
1. TenantContext 未正确设置（检查 TenantFilter 是否生效）
2. 数据属于其他租户
3. 异步任务中未使用 `TenantContext.wrap()`

**调试步骤**：
```java
// 检查当前租户
log.debug("Current tenant: {}", TenantContext.getTenantId().orElse("NOT_SET"));

// 检查数据的 tenant_id
log.debug("Data tenant_id: {}", entity.getTenantId());
```

### Q2: 如何在定时任务中使用租户上下文？

```java
@Scheduled(cron = "0 0 2 * * ?")
public void dailyReport() {
    // 使用系统租户执行全局任务
    TenantContext.runAsSystem(() -> {
        // 1. 获取所有租户
        List<Tenant> tenants = tenantRepository.findAll();
        
        // 2. 为每个租户生成报告
        for (Tenant tenant : tenants) {
            TenantContext.runWithTenant(tenant.getId().toString(), () -> {
                generateReportForTenant(tenant);
            });
        }
    });
}
```

### Q3: 如何处理数据迁移场景？

```java
/**
 * 数据迁移使用宽松模式的验证器
 */
@Service
public class DataMigrationService {

    // 使用宽松模式，仅记录警告而不抛出异常
    private final TenantReferenceValidator validator = 
        new TenantReferenceValidator(false);

    @CrossTenantAccess(reason = "Legacy data migration from single-tenant system")
    public void migrateData(List<LegacyOrder> legacyOrders, String targetTenantId) {
        for (LegacyOrder legacy : legacyOrders) {
            // 宽松模式下的迁移，仅记录警告
            Order order = convertToOrder(legacy);
            order.setTenantId(targetTenantId);
            orderRepository.save(order);
        }
    }
}
```

## 5. 代码示例

### 5.1 完整的 CRUD Service 示例

```java
@Service
@Transactional(readOnly = true)
public class CustomerService {

    private final CustomerRepository customerRepository;
    private final TenantReferenceValidator validator;

    public CustomerService(
            CustomerRepository customerRepository,
            TenantReferenceValidator validator) {
        this.customerRepository = customerRepository;
        this.validator = validator;
    }

    /**
     * 创建客户 - 自动设置 tenant_id
     */
    @Transactional
    public Customer createCustomer(CreateCustomerRequest request) {
        Customer customer = new Customer();
        customer.setName(request.getName());
        customer.setEmail(request.getEmail());
        // tenant_id 由 TenantOwnedEntity 自动设置
        return customerRepository.save(customer);
    }

    /**
     * 查询客户列表 - 自动按租户过滤
     */
    public List<Customer> findCustomers(CustomerSearchCriteria criteria) {
        // TenantInterceptor 自动添加 tenant_id 条件
        return customerRepository.findByCriteria(criteria);
    }

    /**
     * 获取单个客户 - 验证租户归属
     */
    public Customer getCustomer(Long customerId) {
        return customerRepository.findById(customerId)
            .map(customer -> {
                // 验证返回的客户属于当前租户
                validator.validateEntityReference(
                    customer,
                    TenantContext.getCurrentTenantId(),
                    Customer::getTenantId,
                    "Customer", customerId, "id"
                );
                return customer;
            })
            .orElseThrow(() -> new EntityNotFoundException("Customer not found: " + customerId));
    }

    /**
     * 更新客户 - 先验证再更新
     */
    @Transactional
    public Customer updateCustomer(Long customerId, UpdateCustomerRequest request) {
        Customer customer = getCustomer(customerId); // 已包含租户验证
        customer.setName(request.getName());
        customer.setEmail(request.getEmail());
        return customerRepository.save(customer);
    }

    /**
     * 删除客户 - 先验证再删除
     */
    @Transactional
    public void deleteCustomer(Long customerId) {
        Customer customer = getCustomer(customerId); // 已包含租户验证
        customerRepository.delete(customer);
    }
}
```

## 6. 检查清单

### 开发完成前检查

- [ ] 所有业务实体继承 `TenantOwnedEntity`
- [ ] 所有唯一约束包含 `tenant_id`
- [ ] 所有引用关系通过 `TenantReferenceValidator` 验证
- [ ] 所有异步任务使用 `TenantContext.wrap()`
- [ ] 所有跨租户访问标注 `@CrossTenantAccess` 并填写 reason
- [ ] 原生 SQL 查询已手动添加 `tenant_id` 条件

### 代码评审检查

- [ ] 新增表是否包含 `tenant_id` 字段
- [ ] 枚举变更是否影响已有数据
- [ ] 唯一约束中是否包含 `tenant_id`
- [ ] 是否存在未经验证的跨实体引用
