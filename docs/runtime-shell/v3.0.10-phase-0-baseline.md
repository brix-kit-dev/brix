# Brix Runtime Shell v3.0.10 Phase 0 Baseline

> Date: 2026-07-23
> Scope: Phase 0, baseline freeze only
> Architecture baseline: `v3.0.10-运行壳架构设计蓝图.md`
> Implementation plan: `v3.0.10-运行壳架构模型升级改造计划.md` §5, Phase 0

## Phase Scope

Phase 0 freezes the migration baseline for the v3.0.10 Runtime Shell model. It stops the v3.0.9 model from spreading while keeping existing plugins buildable on the compatibility path.

This phase does not implement `BrixPlugin`, `PluginContext`, ServiceLoader discovery, Runtime bootstrap, manifest YAML migration, tenant plugin startup, Host readiness, or the bootstrap-to-first-owner business flow.

## Runtime Model Switch

The migration switch key is:

```properties
brix.runtime-shell.model=3.0.10
```

Phase 0 only establishes the key as the authoritative model selector. Runtime behavior for the key is implemented in later phases by the Runtime Orchestrator and Host bootstrap work.

## Tenant-Only Guard Intent

The tenant-only v3.0.10 gate must remain isolated from other commercial plugins. In this OSS slice, CI validates the shared contract and schema freeze inputs only. The enterprise repository owns the concrete `app-tenant` provider, Host profile, and runtime closure checks once cross-repository writes are available.

Minimum enterprise follow-up command, owned by `brix-enterprise`:

```bash
mvn -pl packages/@brix/enterprise-host/host-shell-standalone -Pci-runtime-shell-3.0.10 test
```

## Rollback Strategy

1. Keep the v3.0.9 compatibility APIs compiling.
2. Keep legacy manifest schemas readable until Phase 3 switches `app-tenant` to the v3.0.10 YAML manifest.
3. Disable the model selector by removing or changing `brix.runtime-shell.model=3.0.10`.
4. Revert only Phase 0 guard and documentation edits; do not change Flyway migrations or business data.

## Phase Exit Evidence

1. `app-tenant` and other enterprise plugins are not modified in this OSS slice.
2. CI contains a v3.0.10 Phase 0 guard entry that can run independently of broad package lint/type checks.
3. OSS contract and manifest documentation no longer describes `RuntimeContext`, `AbstractModule`, `LifecycleCapability`, `module-manifest.yaml`, or JSON `plugin-manifest.json` as the new active Runtime Shell model.
